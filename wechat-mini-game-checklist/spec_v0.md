# 玩法与 UI 规格（v0，来自策划稿落地版）

本文档把你提供的“玩法说明”转换为可直接开发的规格，作为工程实现与验收依据。

---

## 1. 目标与边界

- **项目类型**：微信小游戏（联机割草 / 幸存者类）
- **联机模式**：房间制，最多 **4 人**
- **局时长**：15 分钟
- **地图**：固定大地图起步，大小 **3000×3000**
- **性能目标**：同屏怪物 **300+**（通过对象池、空间哈希与轻量避让保证观感与帧率）
- **装备系统**：每个玩家**装备/武器互相独立**（但经验/等级共享）

---

## 2. 界面层级与交互

### 2.1 主菜单界面

包含按钮：

- **开始游戏**
  - 点击后：创建房间 → 切换到「房间界面」
- **加入房间**
  - 点击后：弹出「加入房间弹窗」

### 2.2 加入房间弹窗

- 标题：**加入房间**
- 输入框：
  - 占位提示：**请输入六位房间号**
  - 当输入非空：占位提示隐藏
- 底部按钮：
  - 左：取消（关闭弹窗）
  - 右：确定
    - 若房间存在且未满员：加入房间 → 切换到「房间界面」
    - 否则：提示错误（房间不存在/已满/已开始/已过期）

### 2.3 房间界面（Room）

进入条件：
- 房主：从主菜单点击「开始游戏」创建房间进入
- 房客：通过加入房间或邀请链接进入

界面布局要点（相对布局，不锁死具体像素）：

- **房间号**：屏幕正中间偏上位置显示（建议格式：`房间号：123456`）
- **左侧玩家列表**：垂直居中，固定 **4 行**
  - 每行从左到右：头像、名称、准备状态
  - 空位行：
    - 头像位显示“灰底加号”
    - 点击加号：打开微信邀请分享（邀请好友进房间）
    - 名称显示 `--`
    - 准备状态为空
- **角色选择区域**：房间号下方
  - 横向循环列表，一次可见 3 个角色
  - 中间为“选中态”
  - 左右箭头：切换选中角色
- **底部主按钮**：角色选择区下方，水平居中
  - 房主视角：显示 **开始游戏**
    - 房主固定为“已准备”状态
    - 点击开始游戏：当满足开局条件时开局
  - 房客视角：显示 **准备**
    - 入房默认未准备
    - 点击准备：切换为已准备（可再次点击取消准备，是否允许由实现定义，默认允许）

开局条件（建议 v0）：
- 至少 1 人在房间（房主）
- 所有在房间的房客均已准备

结算回房间规则：
- 若 15 分钟内全队阵亡：失败 → 返回房间界面
- 返回房间后：
  - 房主保持已准备（房主按钮仍为“开始游戏”）
  - 其他玩家全部重置为未准备

## 2.4 局内 HUD（你口述布局落地版）

- **左上角玩家信息区**：
  - 最多 **4 组**，垂直排列
  - 第 1 行固定显示**本地玩家**信息，后续依次为其他玩家
  - 每组布局：
    - 左侧：玩家头像
    - 右侧：上方血条、下方装备槽位
      - 装备槽位共 **6 个**
      - 每个装备槽位下方显示一个数字代表装备等级
- **上方正中间**：本局已进行时间，格式 `mm:ss`
- **屏幕最下方**：一条横向铺满的经验条
  - 底色：黑色
  - 填充色：米白色
  - 经验条居中上方显示当前等级（数字）

## 3. 局内循环与规则

### 3.1 地图与出生

- 地图尺寸：**3000×3000**
- 单人出生点：`(1500, 1500)`
- 多人出生：
  - 以 `(1500, 1500)` 为中心点
  - 玩家间距 `50`
  - 生成“横向一排”出生点（例如 4 人：从左到右排开）

### 3.2 经验与等级（共享）

- 经验、等级 **全队共享**
  - 任意玩家吃到经验球：全队经验增加
  - 任意玩家触发升级：全队同时升级（进入升级界面）
- 升级带来的“装备变化”是**各玩家独立**的：升级只改变做出选择的玩家自身装备/属性（见 3.3）

### 3.3 升级（三选一 + 暂停 + 倒计时）

触发升级后：
- 游戏进入“暂停态”
- 弹出升级界面，倒计时 **15 秒**
- 倒计时文本显示位置：屏幕中上方标题处
- 升级选项：三选一
  - 默认选中：左侧第 1 个选项
- 确认按钮：屏幕居中下方
  - 点击确认：提交本玩家选择
- 倒计时结束：
  - 若有玩家仍未选择：为其自动选择“当前选中项”（默认即第 1 个）
- 关闭升级界面条件：
  - 全队都完成选择，或倒计时结束（已自动补齐）

实现约定（便于联机一致性，推荐）：
- 升级暂停由**服务器权威**触发与结束（广播升级开始时刻与倒计时起点）
- **每个玩家的三选一选项与选择互相独立**：
  - 服务器为**每个玩家**生成 3 个升级选项并下发（允许不同玩家看到不同选项）
  - 每个玩家只对自己的 3 个选项做选择；选择结果只作用于该玩家自身装备/属性
- 倒计时结束仍未选择时：为该玩家自动选择其“当前选中项”（默认第 1 个）

### 3.4 武器与敌人（v0 约束）

你给的要求是“武器 1:1 复刻吸血鬼幸存者，由我出方案”。已确认 v0 优先武器为：
- **闪电**
- **法术**（实现命名建议：法术飞弹/魔法弹一类的自动索敌投射物）
- **大蒜**

为保证原型推进，建议 v0：

- 先做 **1–3 个武器 + 1–2 个被动**（确保升级循环成立）
- 武器系统必须支持：
  - 等级成长（基础伤害、冷却、数量、范围等）
  - 词条池与权重
  - 未来扩展“进化/合成”（可后置）

敌人系统要求：
- 必须支持可扩展的敌人种类（数据驱动）
- 15 分钟内：
  - 敌人血量、伤害、刷新频率持续走高
  - 同时保证“爽感”与难度随玩家成长同步上升

实现建议（v0）：
- 采用“时间轴参数曲线”驱动刷新与属性（0–15 分钟分段或连续曲线）
- 通过“单位时间怪物预算”控制同屏数量与刷怪节奏（避免突刺卡顿）

### 3.5 胜负条件

- 15 分钟结束：
  - 若剩余存活玩家 > 0：胜利
- 15 分钟内：
  - 若所有玩家都阵亡：失败，回到房间界面（并重置非房主准备状态）

## 4. 联机同步清单（来自策划稿 + 落地建议）

你原稿的同步项（原样保留）：
- 各玩家的坐标、旋转、血量、攻击特效
- 游戏内的飞行物（敌人/队友的攻击飞行物等）
- 游戏地图里的掉落物（吸铁石、血包等）
- 玩家等级、经验共享、同步
- 地图内所有敌人的坐标、旋转、血量、攻击特效

落地补充（建议 v0 增补，否则容易不同步/复现 bug 困难）：
- **房间状态**：房间号、玩家列表、角色选择、准备状态、房主 ID、开局倒计时（如有）
- **游戏阶段**：Lobby / InGame / LevelUpPause / Result
- **升级暂停**：
  - 广播升级开始、倒计时起点
  - 广播三选一选项（ID + 参数）
  - 收集每个玩家的选择与最终落地结果
- **随机性**：所有随机（掉落、刷怪、升级选项）由服务器决定并广播结果
