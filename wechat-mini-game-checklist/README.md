# 微信小游戏（联机割草原型）从 0 到上架清单

> 目标：你主要负责**策划与数值**（≈5%），其余工程/联机/工具链/打包/接入由我完成（≈95%）。
>
> 推荐技术路线（尽量不依赖拖拽编辑器）：
> - 客户端：**微信小游戏 + TypeScript + Phaser 3**
> - 地图：**Tiled**（固定大地图起步，预留 chunk/room 扩展）
> - 联机服务端：**Node.js + Colyseus（WSS）**
> - 排行榜：微信**开放数据**（好友榜/群榜）+ `wx.setUserCloudStorage`
> - 邀请入房：`wx.shareAppMessage` 携带 `roomId/inviteCode`

## 1. 立项规格（避免返工的最小决策）

### 1.1 核心玩法（MVP 固定范围）
- [ ] 局长：例如 10/15 分钟
- [ ] 升级：三选一、升级池规则、重复与进化规则
- [ ] 结算：胜利/失败判定、结算指标（分数/击杀/生存时间）
- [ ] 联机：**2 人合作优先**（强烈建议原型先锁 2 人）

### 1.2 同屏怪物目标与性能约束
- [ ] 目标同屏怪：**300+**
- [ ] 可接受的观感：怪群不堆叠成一个点即可（无需完整 RVO）
- [ ] 机型策略：给出最低目标机型（例如“近三年中端安卓”）与降级开关策略

### 1.3 美术与素材策略（原型期）
- [ ] 占位素材/几何体先跑通
- [ ] 后续替换素材需要：统一命名与目录规范、尺寸规范、授权证明（上线前）

**你负责**

**我负责**
- [ ] 输出：可执行的技术规格（tick、同步频率、对象池、怪物上限与降级）

## 2. 地图工作流（固定大地图起步 + 预留程序生成）

### 2.1 原型期：固定大地图
- [ ] 使用 Tiled 新建地图（建议 JSON 导出）
- [ ] 按模板创建图层：
  - [ ] `Ground`（地表 tile）
  - [ ] `Deco`（装饰 tile）
  - [ ] `Block`（阻挡：tile 或对象多边形）
  - [ ] `Objects`（出生点/刷怪区/事件触发器）

### 2.2 为程序生成预留：chunk/room 兼容
- [ ] 约定将来支持两种加载方式：
  - [ ] `world.json`（固定大地图）
  - [ ] `chunks/<chunk_id>.json` + `manifest.json`（房间块/分块拼接）
- [ ] 在 `Objects` 层使用“数据驱动实体”（未来随机也能复用）：
  - [ ] `PlayerSpawn`
  - [ ] `MobSpawnZone`（刷怪区：怪物类型、权重、密度/频率）
  - [ ] `EliteSpawn` / `BossSpawn`
  - [ ] `Portal` / `Trigger`

**你负责**
- [ ] 用 Tiled 画地图、放点位（按模板）

**我负责**
- [ ] 写导入器、校验器、运行时调试显示（碰撞/触发器可视化）
- [ ] 定义 `manifest.json` 结构，保证未来可无痛切换到程序生成

## 5. “不堆叠”的轻量避让（替代完整版 RVO）

> 目标：同屏 300+ 怪时，怪群拥挤但不重叠成一个点，观感稳定且保帧。

- [ ] 空间哈希分桶（同格+邻格取邻居）
- [ ] 分离力（separation）+ 软推挤（soft collision）
- [ ] 少量切向绕行倾向（避免全都直线硬挤）
- [ ] 更新频率：逻辑 10–20Hz，渲染插值
- [ ] 精英/大体型权重更大，小怪更易被挤开

---

## 6. 联机（服务器权威，最稳也最不容易不同步）

### 6.1 房间与流程
- [ ] 创建/加入房间
- [ ] Ready → Start → 结算 → 回大厅
- [ ] 房间 TTL（邀请后未开局自动释放）

### 6.2 同步模型（建议）
- [ ] 客户端只发：输入（方向、确认升级选择等）
- [ ] 服务端权威：刷怪、碰撞、掉落、升级随机
- [ ] 广播：世界快照/增量（10–20Hz）
- [ ] 客户端：插值/平滑显示（原型可先不做预测）

### 6.3 断线策略（先易后难）
- [ ] v1：掉线回大厅（提示重进）
- [ ] v2：断线重连补快照（可选）

## 7. 好友排名（微信开放数据：好友榜 + 群榜）

> 注意：微信不允许你随意枚举好友列表；“好友排名”要通过开放数据接口获取允许范围内的数据。

- [ ] 成绩上报：`wx.setUserCloudStorage`（例如 key：`bestScore` / `bestTime`）
- [ ] 好友榜：`wx.getFriendCloudStorage`
- [ ] 群榜（推荐）：分享进群后可用 `wx.getGroupCloudStorage`
- [ ] 展示方式：开放数据域/OpenDataContext 绘制排行榜面板
- [ ] 防刷：服务端权威结算后回传成绩，再由客户端写入云存储（避免本地篡改）
